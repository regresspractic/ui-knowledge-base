# Техническое задание: AI-партнёр для экспертов — MVP
**Дата:** 05.06.2026  
**Статус:** MVP, Вариант 1 (один клиент = один бот)

---

## 1. ЧТО МЫ СТРОИМ

Telegram-бот — AI-партнёр по контенту для экспертов с личным брендом.

**Главный принцип:** бот сохраняет голос автора, не приглаживает под AI.

**Отличие от ChatGPT:**
- Помнит эксперта месяцами
- Знает её продукты, аудиторию, стиль
- Сопровождает процесс создания контента
- Становится частью рабочего процесса

## 3. СТРУКТУРА ПАПОК НА VPS

```
/home/USER/bots/
    template/          ← эталонный шаблон (не трогать)
    olga/              ← бот Ольги
    client2/           ← следующий клиент
    client3/           ← и так далее
```

**Внутри каждой папки клиента:**

```
telegram_bot.py       — основной бот
voice_profiles.py     — стиль автора (промпт-профиль)
dialog_flow.py        — load_archive, save_to_archive, вопросы диалога
dialog_handler.py     — AUTHOR_STYLES
profile.json          — данные клиента (не в GitHub)
archive.jsonl         — архив записей (не в GitHub)
.env                  — токены (не в GitHub)
.env.example          — заглушки (в GitHub)
```

**Файл `.gitignore` (обязательно):**
```
.env
archive.jsonl
profile.json
```

## 4. ПРОФИЛЬ КЛИЕНТА — `profile.json`

```json
{
  "name": "Ольга",
  "topic": "психология отношений",
  "audience": "женщины 35-50, в поиске себя",
  "style": "тепло, без жаргона, короткие предложения",
  "tone": "мягкий, поддерживающий, без менторства",
  "products": ["индивидуальные сессии", "группа поддержки"],
  "channels": {
    "telegram": "@olga_example",
    "instagram": "@olga_example"
  },
  "forbidden": ["советовать", "осуждать", "использовать слово трансформация"],
  "examples": []
}
```

**Поля:**
- `name` — бот обращается по имени
- `topic` — контекст для генерации
- `audience` — для кого пишем
- `style` — голос автора
- `tone` — манера говорить
- `products` — чтобы не выдумывать несуществующее
- `channels` — для онбординга и анализа
- `forbidden` — антигаллюцинация (священные правила)
- `examples` — лучшие посты для памяти

## 5. ОНБОРДИНГ (первый вход)

Вопросы идут **по одному** — не анкета, а живой диалог.

**Шаг 1 — приветствие:**
```
Привет! Я твой AI-партнёр по контенту.
Буду помогать превращать твои мысли в посты,
привлекать клиентов и развивать личный бренд —
сохраняя твой голос, не приглаживая под AI.

Для начала — два быстрых вопроса.
```

**Шаг 2 — вопрос 1:**
```
Как к тебе обращаться?
```
*Клиент отвечает как угодно — "Оля", "Оленька", "Ольга Петровна". Бот берёт ответ как есть и сохраняет в `profile.json → name`. Не переименовывать.*

**Шаг 3 — вопрос 2:**
```
Рад знакомству, Ольга!
Пришли ссылки на свой Telegram и Instagram —
я изучу твои каналы и подстроюсь под тебя.
```
*Ольга присылает ссылки*

**Шаг 4 — анализ и подтверждение:**
```
Вот что я поняла о тебе, Ольга:
— Ты пишешь о [тема]
— Твоя аудитория: [аудитория]
— Твой стиль и голос: [описание]

Всё верно? Или поправить?
```
*Ольга правит или подтверждает → данные сохраняются в `profile.json`*

**Шаг 5 — первое действие:**
```
Отлично! Запиши голосовое — любую мысль.
Сделаем пост, сторис, сценарий для reels —
или сохраним в архиве и вернёмся к этой мысли,
когда будет время.
```

## 7. ЧТО ПРОИСХОДИТ ПОСЛЕ КАЖДОЙ КНОПКИ

### ✍️ Пост
→ Готовый текст в стиле автора.

Кнопки после поста:
```
✏️ Доработать   ◀️ Оригинал   💾 Сохранить
```

**Доработка:** голосом или текстом.  
Примеры команд: "добавь эмоций", "убавь юмор", "сделай короче", "сделай повеселее".  
Цикл открыт — можно дорабатывать несколько раз.

---

### 📱 Сторис
→ Тезисы для слайдов.

---

### 🎬 Reels
→ Сценарий: хук + тело + финал + подписи.

---

### 💬 Поговорим об этом
→ Бот задаёт вопросы по одному (3 вопроса).

После третьего вопроса:
```
Хочешь поговорить ещё? Или достаточно?
```

Если **ещё** → бот задаёт новые вопросы.

Если **достаточно** → бот спрашивает:
```
Что делаем с этой мыслью?

✍️ Пост   📱 Сторис   🎬 Reels
```

---

### 💾 Сохранить и вернуться позже
→ Запись уходит в архив.

Бот отвечает:
```
Сохранил. Вернёмся к этой мысли, когда будешь готова.
```

## 8. АРХИВ

- Файл: `archive.jsonl`
- Структура по датам, новые записи сверху
- Команда `/archive` — показывает записи `source: "user"`
- Разговоры сохраняются с кнопкой «✍️ Сделать пост»

**Формат одной записи:**
```json
{
  "author": "olga",
  "text": "Текст поста",
  "source": "user",
  "date": "2026-06-05"
}
```

**Типы записей:**
- `source: "user"` — сохранила сама (показывается в архиве)
- `source: "channel"` — образцовые посты для памяти (только для промпта)

## 9. ПАМЯТЬ

Перед каждой генерацией бот берёт последние 50 записей из архива как примеры стиля.

Память накапливается через работу — не через анкету.

## 10. СВЯЩЕННЫЕ ПРАВИЛА (в каждый промпт)

```
Запрещено:
— выдумывать факты, которых не было во вводе
— терять голос автора
— добавлять чужие идеи как свои
— менять позицию эксперта без разрешения
— использовать AI-гладкость и канцелярит

Главный принцип:
Сохранение аутентичности важнее идеальной литературности.
```

## 11. ДЕПЛОЙ НОВОГО КЛИЕНТА

```bash
# Шаг 1 — скопировать шаблон
cp -r ~/bots/template ~/bots/имя_клиента

# Шаг 2 — заполнить токены
nano ~/bots/имя_клиента/.env

# Шаг 3 — заполнить профиль
nano ~/bots/имя_клиента/profile.json

# Шаг 4 — запустить сервис
sudo systemctl start имя_клиента.service

# Шаг 5 — проверить
sudo systemctl status имя_клиента.service
sudo journalctl -u имя_клиента.service -n 50
```

## 12. ИЗВЕСТНЫЕ БАГИ — ЗАЛОЖИТЬ РЕШЕНИЯ СРАЗУ

| # | Баг | Рекомендация |
|---|---|---|
| 1 | Задаёт 1 вопрос вместо 3 | Проверить логику `dialog_step` |
| 2 | Не различает разговор и наговор поста | Добавить явную кнопку выбора |
| 3 | Не распознаёт голосовые >20 сек | Увеличить таймаут |
| 4 | Нет возврата к сохранённому разговору | Добавить «Продолжить незавершённое» в меню |
| 5 | Голос автора не совпадает в постах | Улучшить промпт-профиль + больше примеров |

---

## 13. СЛЕДУЮЩИЕ ШАГИ ПОСЛЕ MVP

1. «Продолжить незавершённое» — показывать сохранённые разговоры с кнопкой «Сделать пост»
2. Улучшение голоса автора — больше образцовых постов + доработка промпта
3. Накопление голосовых — несколько коротких записей в одну мысль
4. Аналитика — какие посты сработали
5. Вариант 2 — один бот, все клиенты внутри (масштабирование)

## 15. РАБОЧИЕ ПРАВИЛА

1. Backup/commit **перед** любыми изменениями
2. Инструкции пошагово: 1 шаг = 1 действие
3. Сначала выяснить что работает — потом менять
4. Рабочее состояние важнее новых функций
5. Всегда иметь путь отката
6. Указывать полный путь к файлу, не говорить «открой файл»

**Приоритеты:** рабочее состояние → контекст → данные → настройки → новые функции
